  1. Live bugs in newimpl today

  The exchange can be wedged by one digit. pulse_reg.v:111
  (newimpl/rtl/pulse_reg.v#L111) gates the no-digit timer on ndig == 3'd0. The
  instant the first digit lands the counter stops and nodig can never fire.
  mini_marker's S_COLLECT exits only on r_gone/r_nodig/enough digits, and
  top_min has one register — so a caller who dials one digit and stays off-hook
  locks the exchange out of service until he hangs up. register.md:288 defines
  gone as "CLR, or a partial-dial timeout"; marker.md:306 says the timer "runs
  from the last digit as well as from seizure". An agent reproduced it: +5 s
  silent: state=1 r_busy=1 ndig=1, second lift ignored.

  Why it reached for ndig==0 — pulse_rx.v:45 (newimpl/rtl/pulse_rx.v#L45) assign
  counting = (cnt != 4'd0), and cnt is never cleared at the strobe, so counting
  latches high for the whole call. register.md:205 clears the '163
  synchronously on STB; verilog/ does it. The old tree's !p_counting rule was
  therefore unusable here. Fix is not clearing cnt at dig_stb — pulse_reg.v:102
  (newimpl/rtl/pulse_reg.v#L102) samples cnt in the strobe cycle, so that stores
  0 for every digit. One line: assign counting = (cnt != 4'd0) && !done;.

  A port's /HA address is its board position, not its shunt column. port.v:93
  (newimpl/rtl/port.v#L93) compares scan against {BLOCK, POS} where BLOCK is the
  instance index; C and the write bus both go through SHUNT (mainboard.v:96
  (newimpl/rtl/mainboard.v#L96)), and mainboard.v:90
  (newimpl/rtl/mainboard.v#L90)'s wired-OR is ungated where hc and blk_n are
  gated by SHUNT_FITTED. Latent only because every bench passes the identity
  permutation. mainboard.md:470 ("all three columns run the same way about") is
  now false.

  Two gates that cannot fail. make lint (Makefile:56-62
  (newimpl/Makefile#L56-L62)) runs verilator ... && echo clean in a for; a
  failure on the left of && is exempt from set -e and the loop returns the last
  iteration — only top_min, eleventh of eleven, can fail it. And inside the
  advertised "103 checks": tb_ha.v:205 (newimpl/tb/tb_ha.v#L205) is a
